1. Parent-Child Retrieval hota kya hai?

Normal RAG mein hum document ko chunks mein todte hain:

PDF
 ↓
Chunk 1
Chunk 2
Chunk 3
Chunk 4
 ↓
Embedding
 ↓
Vector DB

Problem ye hai ki agar chunks bahut small hain, retrieval accurate ho sakta hai, lekin context incomplete mil sakta hai.

Example:

Parent Document
└── MongoDB
    ├── Introduction
    ├── Collection
    ├── Document
    ├── Query
    └── Index

Hum search ke liye small child chunks banayenge:

Parent
 ├── Child 1 → "A collection is..."
 ├── Child 2 → "A document is..."
 ├── Child 3 → "MongoDB supports..."
 └── Child 4 → "Indexes improve..."

Vector DB mein child chunks ke embeddings store honge.

Lekin retrieval ke baad hum sirf child nahi denge.

User Question
      ↓
Search Child Chunks
      ↓
Matched Child
      ↓
Find Parent
      ↓
Return Parent Context
      ↓
LLM
Core idea

Small chunks for better retrieval, larger parent chunks for better context.

Ye Parent-Child Retrieval ka sabse important point hai.

3. Ek real example

Suppose PDF mein ye content hai:

MongoDB

MongoDB is a NoSQL database designed for scalability.

Collection

A collection is a group of related documents, similar to a table in SQL.
Collections can contain multiple documents.

Document

A document is a JSON-like record stored inside a MongoDB collection.
Documents can have different structures.

Agar hum small chunks banate hain:

child-1:
"Collection is a group of related documents..."

child-2:
"Collections can contain multiple documents."

child-3:
"Document is a JSON-like record..."

User asks:

What is a collection?

Child search:

child-1 → high similarity

Lekin agar child-1 bahut chhota hai, LLM ko surrounding information nahi milegi.

Isliye:

child-1
   ↓
parent-collection-section
   ↓
"A collection is...
 Collections can contain...
 ..."

LLM ko richer context milega.

7. Parent chunks create karna

Tum already RecursiveCharacterTextSplitter use kar chuki ho.

Parent ke liye:

const parentSplitter = new RecursiveCharacterTextSplitter({
  chunkSize: 1000,
  chunkOverlap: 100,
});

const parentDocs = await parentSplitter.splitDocuments(docs);

Ab maan lo:

parentDocs = [
  parent1,
  parent2,
  parent3
];

Har parent ko ID deni hai:

const parents = parentDocs.map((doc, index) => ({
  parentId: `parent-${index + 1}`,
  text: doc.pageContent,
}));
8. Ab child chunks

Har parent ko further small chunks mein todna hai.

const childSplitter = new RecursiveCharacterTextSplitter({
  chunkSize: 300,
  chunkOverlap: 50,
});

Phir:

for (const parent of parents) {
  const childDocs = await childSplitter.createDocuments([parent.text]);

  console.log(childDocs);
}

Conceptually:

parent-1
   ↓
child-1
child-2
child-3

Aur metadata:

{
  childId: "child-1",
  parentId: "parent-1"
}
